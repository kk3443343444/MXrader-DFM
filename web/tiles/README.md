# 雷达底图瓦片（`web/tiles/`）

本目录存放**离线瓦片底图**。页面在局域网内运行，**不允许外网 CDN**，所以所有底图都必须
预先放好；缺失的瓦片不会报错，会自动回退到内联的「离线占位图」。

## 1. 目录布局

```
web/tiles/
  README.md                 ← 本文件
  ZeroDam/
    0/0/0.png
    1/0/0.png  1/1/0.png
    1/0/1.png  1/1/1.png
    ...
    6/{x}/{y}.png           ← 常用缩放级别
  Layali/...
  Bakesh/...
  Brakesh/...
  SpaceCity/...
```

URL 模板（服务器 `/ws` 的 `hello.tile_template` 字段给出，默认）：

```
/tiles/{map}/{z}/{x}/{y}.png
```

- `{map}` → 地图键（与 `hello.map` 一致，见下表）
- `{z}`   → 整数缩放级别（Leaflet 标准：z=0 时全图为 1 块 256×256 瓦片，每加一级 ×2）
- `{x}`   → 该 z 级别下的列号，范围 `0 .. 2^z - 1`
- `{y}`   → 该 z 级别下的行号，范围 `0 .. 2^z - 1`，**从上（北）往下递增**（Web Mercator / TMS 翻转前的 XYZ 约定）

瓦片必须是正方形 PNG（默认按 256×256 处理），边缘无需留缝。

`hello.map` 出现的键若无对应目录，页面会照常运行，只是整张底图显示为离线占位图。

## 3. 占位图回退

`leaflet-lite.js` 里的 `L.offlineTilePng` 是一段内联的 16×16 PNG data URI（`#15171f` 底 + `#262a36` 斜线）。
任何瓦片请求失败（404 / 超时 / 解码失败）时，`Image.onerror` 会把该瓦片切到这张占位图，
因此：

- 不会出现浏览器默认的「裂图」图标；
- 不会产生新的网络请求（占位图是内联 data URI，符合零外网依赖要求）；
- 地图上仍能看到网格（占位图缩放后即为一格一格的暗色砖），方便判断当前 z/x/y 覆盖范围。

## 4. 标定（`web/maps.json`）——**必须按游戏版本重新标定**

`web/maps.json` 是每张地图的**投影与转向标定表**，`radar.js` 用它把世界坐标（米，Z 向上）
投影到地图经纬度：

```
lng = origin_x + x * scale          // x = 世界东向坐标（米）
lat = origin_y + z * scale          // z = 世界北向坐标（米）
```

单位假设：`origin_x/origin_y` 是**度**，`scale` 是**度/米**（地图按等距圆柱近似成一小块矩形）。
`y < 0` 的滚转角在投影时被忽略（radar 只需要平面投影）。

### 4.1 用两个已知地标标定 `origin_*` 与 `scale`

1. 进游戏同一张图，站在**地标 A**（例如大坝主闸门中心），记录游戏内坐标 `(x_A, z_A)` 与
   该点在你底图上的像素坐标 `(px_A, py_A)`。
2. 再站到**地标 B**（尽量远，例如地图对角的一栋楼顶），记录 `(x_B, z_B)` / `(px_B, py_B)`。
3. 先把底图配成已知的 `tiles/<map>/<z>/<x>/<y>.png` 网格：记住 `z` 级别下 1 瓦片 = 256 px，
   全图 360° 经度 → `256 * 2^z` px，纬度按 Web Mercator。
   实际做法：任选一点算它落在哪个瓦片上，即可把像素换算成经纬度。
4. 两个地标联立解出：

```
scale = (lng_B - lng_A) / (x_B - x_A)     // 应与 (lat_B - lat_A)/(z_B - z_A) 一致，不一致说明比例尺或底图 z 级别选错
origin_x = lng_A - x_A * scale
origin_y = lat_A - z_A * scale
```

5. 把结果写回 `maps.json` 对应地图键；`min_x/min_y/max_x/max_y` 填世界米制范围，页面的初始
   缩放级别就按这个范围自适应。

### 4.2 「3D 转向修正」的两个旋钮

`radar.js` 的箭头朝向 = `yaw_sign * yaw + yaw_offset_deg`，其中 `yaw` 是服务器下发的值。
**默认是恒等标定（`yaw_sign = 1`、`yaw_offset_deg = 0`）**，因为 INTERFACES.md §5 已明确规定
下发的 `yaw` 就满足「0 = 正北、顺时针为正」，与画布朝向一致，此时不需要任何额外修正。
只有在下列情况才需要动这两个旋钮：

- 某个地图/协议版本下发的是**原始 UE yaw**（0 = 正东、逆时针为正）→ 需要 `yaw_offset_deg = -90`；
- 方向整体镜像反了（你往左转、箭头往右转）→ 翻 `yaw_sign` 为 `-1`；
- 方向整体差一个固定角度 → 调 `yaw_offset_deg`（每次 ±5°）。

- **`yaw_offset_deg`**：固定角度偏移旋钮。
- **`yaw_sign`**：`+1 / -1`，方向旋钮。

标定方法：找一处**能明确朝向**的场景（面朝地图正北站定，或让别人站在你正前方），
在页面上点「跟随朝向」模式观察箭头；再切到「3D」确认俯仰时箭头的长短收缩方向正确
（抬头/低头时地面上的前向向量按 `cos(pitch)` 缩短，低头到极限时箭头反向）。

`mode === '3d'` 时还会叠加 `pitch/roll` 修正：俯仰角越大，地面上的前向向量被压缩得越短
（`foreshortening = |cos(pitch)|`），roll 则给箭头一个等量的屏幕倾斜，用来贴合玩家真实视线方向。

## 5. 新增地图检查清单

1. 建目录 `web/tiles/<MapKey>/`，放入 `z/x/y.png`。
2. 在 `web/maps.json` 增加同名键，按 §4.1 标定 4 个数值 + 2 个旋钮 + 范围。
3. 确认服务器 `/ws` 的 `hello.tile_template` 仍为 `/tiles/{map}/{z}/{x}/{y}.png`（或在此登记差异）。
4. 打开 `battle.html?brand=mx`，看「诊断」面板里的 `tiles_loaded` 计数是否增长。
